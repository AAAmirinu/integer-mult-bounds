# Stage-conditioned donor-flag portfolio

## Sufficient construction

Take two concrete, independently checked local programs with the same source/target endpoint map and the same target labels. Each returns arbitrary dirty helpers and private work to their specified final states. Here provider11 has eleven nested-frame upgrades and provider1 has one; both additionally use the new response-preserving injection relocation. Use provider1 at stages 2,4,6,8 in all eight replicas, provider11 at all other stages. A chronological composition can replace each local program by its endpoint map because complete invocations, rather than fragments, are dispatched. Thus the existing eleven-stage endpoint identity is preserved. This requires no statistical independence between dirty helpers.

For each provider, retain its exact source word hash, native record hash, local forward/reverse program hashes, starting frame list, explicit rational residual isometries, and isometry hash. Every occurrence selects its provider by its orientation and call registry. The physical assignment maps each complete residual to ONE family, an idle child, and a contiguous coordinate interval of exactly its active width. Its chronological stage lies inside that child's independently re-derived window. All selected intervals are globally disjoint. Consequently the inherited whole-family hosting theorem applies occurrence by occurrence; there is no cross-family factorization assumption.

The packing selection is an explicit integer witness. Checking it needs no optimizer. Reconstruct every local program call and every remaining idle child, then count the paid ranks. Local savings and packing savings are not added. Recompute the cancellation-free row-L1 bound along every emitted scalar update on the actual physical owner families; identical-family aliases affect the same bound variable. This yields the finite precision/work invoice required by the inherited assembly.

## Why the inventory choice helps

The smaller-entrance provider has cheaper local frame transitions but larger residual widths. Stages 2,4,6,8 alone can access rank-7 one-stage idle children; the other stages access different windows. An identical local word everywhere ignores this difference. Configuration optimization can choose a costlier local word precisely where its smaller residual inventory saves more paid idle work. This is a compiler register-allocation / configuration-LP crossover. Heterogeneous providers themselves were already implemented in the earlier R740 weave campaign, so the novelty claim is specifically stage-conditioned choice among nested donor flags on R715, composed with response-syndrome retiming, not invention of heterogeneous dispatch.
